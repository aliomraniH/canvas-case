Highlights

Providers can now double-click any weight datapoint on the Weight Trajectory chart to open a small read-only panel showing the measurement's weight, date, data provenance, and the GLP-1 dose in effect on that date. The dose is resolved point-in-time — a past measurement shows the agent/dose that covered that date, not today's prescription — and degrades to “No dose on record” when there is no GLP-1 medication. Nothing is written; the panel is purely a read-time lens over data the chart already loads. Closes with × or Esc. Existing behavior (hover tooltip, Shift+D diagnostics, Export) is unchanged.

What it looks like

Bugs found & fixed

The Phase-1 code was built and merged in a web container that could not run the SDK or pytest, so it reached CLI deploy with latent issues caught here:

  • Dose always blank. The dose resolver read getattr(med,"quantity") or getattr(med,"dose") — neither field exists on the 0.163.1 Medication model. The real display field is clinical_quantity_description. One-line fix; live result is “Wegovy 0.5 mg/0.5 mL pen” / “Zepbound 2.5 mg/0.5 mL pen”.
  • Red mock gate (5 failures). The merged build left PLUGIN_VERSION at 0.5.0 while the manifest was bumped to 0.6.0 (3 version-pair tests), changed the footer hint copy without updating its verbatim pin (1), and a stateful deploy-guard test had no isolation so an inherited counter made it emit “REPEATED BLOCK” instead of “BLOCKED” (1). All fixed → 259 passed / 0 skipped / 0 failed.
  • Coverage-period fields. Candidate period_start/period_end do not exist; live fields are start_date/end_date (already in the fallback list, so periods resolved — reordered verified-first).

Observations & architectural findings (SDK 0.163.1)

Medicationperiod = start_date / end_date; display dose = clinical_quantity_description; no quantity/dose field
Noteauthor = provider (care-team detection works); no origin/source/patient_reported; NoteTypes has no patient-portal value → “patient self-entered” provenance not derivable live

Because every seeded note carries a provider, all live points classified as “Care-team entry.” That is the honest, correct fallback — not a bug.

Future-version considerations

  • Provenance signal coverage. “Automatic scale” / “Patient self-entered” have no reliable source field in 0.163.x. Revisit if a later SDK exposes a device or patient-reported origin, or seed a patient-portal weight fixture to exercise the branch.
  • Past-dose vs. today. The period-aware resolver is in place, but no seeded patient switches agents, so the strict “past dose ≠ current dose” case is unproven live — add a med-switch fixture.
  • Phases 2–4 (per the plugin spec) are independent of this read-only panel.
